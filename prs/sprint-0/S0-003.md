# S0-003 — Add Typed Application Settings

**Area:** Platform / Configuration  
**Priority:** P0  
**Depends On:** S0-001,S0-002  
**Issue:** Closes #4

**Objective**

- Load application configuration through one typed Pydantic settings boundary.
- Select the correct PostgreSQL database by environment and reject unsafe production or test values before application startup.

**Changes**

- Add `AppEnvironment` values for development, test, and production.
- Add typed application, PostgreSQL, Redis, host, CORS, cookie, secret, timeout, and startup-check settings.
- Load settings from `.env` and `EKUMIDAYOMI_`-prefixed environment variables.
- Add `active_database_url` so test mode uses the dedicated test database URL.
- Reject identical development and test database URLs in test mode.
- Reject debug mode, insecure cookies, wildcard hosts, wildcard origins, empty hosts, and placeholder secrets in production.
- Add a cached process-wide `get_settings()` accessor.
- Export the settings contract from `ekumidayomi.core`.
- Add focused unit tests for environment branches, list parsing, secret masking, caching, test-database isolation, every production safety rule, and active database selection.

**Acceptance Criteria**

- Application modules can obtain configuration from one typed settings module.
- `APP_ENV=test` selects `test_database_url` rather than `database_url`.
- Test mode rejects a test database URL that is identical to the development database URL.
- Production mode rejects debug mode.
- Production mode requires secure cookies.
- Production mode rejects wildcard allowed hosts and CORS origins.
- Production mode rejects an empty allowed-host list.
- Production mode rejects known placeholder secret keys.
- Secret fields use Pydantic's secret-aware representation.
- `get_settings()` returns a cached validated settings instance.
- Ruff formatting and linting pass for all S0-003 files.
- Strict mypy validation passes for all S0-003 files.
- All focused S0-003 unit tests pass.

**Validation**

- Run `uv run ruff format --check src/ekumidayomi/core/settings.py src/ekumidayomi/core/__init__.py src/ekumidayomi/tests/unit/core`.
- Run `uv run ruff check src/ekumidayomi/core/settings.py src/ekumidayomi/core/__init__.py src/ekumidayomi/tests/unit/core`.
- Run `uv run mypy src/ekumidayomi/core/settings.py src/ekumidayomi/core/__init__.py src/ekumidayomi/tests/unit/core/test_settings.py`.
- Run `uv run pytest src/ekumidayomi/tests/unit/core/test_settings.py`.

**Done When**

- Later application and infrastructure work can consume one validated settings object without reading environment variables directly.
- Unsafe production and shared test-database configurations fail during settings validation.
- All focused S0-003 unit tests and quality checks pass.
